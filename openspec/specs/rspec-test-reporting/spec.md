# rspec-test-reporting Specification

## Purpose

Lets an RSpec test suite report its start/pass/fail lifecycle to `agentd`, and lets a project opt into that reporting without editing any file it already tracks in version control.

## Requirements

### Requirement: RSpec formatter reports test-run lifecycle events
The RSpec formatter SHALL report a "started" event when a test run begins, and a "passed" or "failed" event when it completes, based on whether the run had any failing examples. Each event SHALL carry the working directory the run was invoked from.

#### Scenario: Test run starts
- **WHEN** an RSpec run begins with the formatter loaded
- **THEN** the formatter reports a "started" test-run event carrying its working directory to `agentd`

#### Scenario: Test run completes with no failures
- **WHEN** an RSpec run finishes and no example failed
- **THEN** the formatter reports a "passed" test-run event

#### Scenario: Test run completes with failures
- **WHEN** an RSpec run finishes and at least one example failed
- **THEN** the formatter reports a "failed" test-run event

### Requirement: Formatter identifies a run by working directory only
The formatter SHALL identify its test run to `agentd` using only its working directory. It SHALL NOT attempt to determine or report a Claude Code session id or a process-ancestry-derived identity, since a test run may be launched from an agent's own tool call, from an editor, or from an unrelated terminal, and none of those provide a reliable session id to the formatter's process.

#### Scenario: Run launched outside any agent
- **WHEN** an RSpec run is started from a terminal or editor with no Claude Code agent involved
- **THEN** the formatter still reports its working directory and status normally, without attempting session correlation

### Requirement: Reporting never blocks or affects the test run
Sending a test-run event to `agentd` SHALL be bounded by a short timeout and SHALL NOT change the test run's exit status, duration in any user-visible way, or output on failure to reach the daemon (for example, because it is not running).

#### Scenario: Daemon is unreachable
- **WHEN** the formatter cannot connect to or send to `agentd`'s socket
- **THEN** the RSpec run completes and reports its normal exit status as if the formatter were not reporting anywhere

### Requirement: CLI command generates a project's .rspec-local
`agentmon` SHALL provide a subcommand that writes a `.rspec-local` file in the current directory containing the `--require` and `--format` options needed to load the installed formatter, without modifying the project's tracked `.rspec` file. Running the subcommand again SHALL NOT duplicate these options if they are already present.

#### Scenario: First-time setup in a Rails project
- **WHEN** the user runs the subcommand in a project's root directory that has no `.rspec-local`
- **THEN** `agentmon` creates `.rspec-local` with `--require`/`--format` pointing at the installed formatter, and leaves `.rspec` untouched

#### Scenario: Running the command again is a no-op
- **WHEN** the user runs the subcommand again in a directory whose `.rspec-local` already contains the generated options
- **THEN** `agentmon` does not duplicate or otherwise change those options

### Requirement: Formatter is installed at a stable path across upgrades
The formatter SHALL be installed by the Homebrew package at a path that does not change between versions, so a `.rspec-local` generated by an older version continues to resolve correctly after a `brew upgrade`.

#### Scenario: Package is upgraded after .rspec-local was generated
- **WHEN** the user runs `brew upgrade` for the package after having generated a project's `.rspec-local`
- **THEN** the path referenced in that `.rspec-local` still resolves to the newly installed formatter
